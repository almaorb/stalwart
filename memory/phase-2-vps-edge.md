# Phase 2 plan: almaorb.dev as the public edge (NOT done yet)

Goal: the Mac keeps the mailboxes; the VPS almaorb.dev (mail.almaorb.com, 72.60.169.136, static
IP, port 25 open) faces the internet. The VPS Stalwart already serves actionagent.ai and
dishorb.com — do not disturb those.

## Inbound (internet → VPS → Mac)

- Tunnel from the VPS to the Mac's 127.0.0.1:12525 (e.g. the existing mac-tunnel / an SSH reverse
  forward / WireGuard). Port 12525 **requires a PROXY header** from 127.0.0.1.
- Option A (preferred if the VPS Stalwart stays the MX for everything): on the VPS, add a relay
  route for the Mac's domains (`learnvibe.ai`, later more) to the tunnel endpoint, and accept those
  domains as relay domains there. Stalwart's outbound relay does **not** send a PROXY header, so
  either (a) put a tiny TCP proxy on the VPS between Stalwart and the tunnel that adds a PROXY v1
  header with destination port 25 (e.g. haproxy `send-proxy`), so the Mac applies its port-25
  inbound rules (the source IP it sees is then the VPS, so SPF must be judged on the VPS), or
  (b) add a second Mac listener without PROXY (e.g. 127.0.0.1:12526) and trust the VPS as a relay
  (the VPS already ran SPF/DKIM/DMARC). Decide in phase 2.
- Option B: L4 pass-through (haproxy with `send-proxy-v2` on :25 → tunnel → 12525) gives the Mac
  the real client IP and full inbound checks, but port 25 can only go one place, so it works only
  when every domain on the VPS has moved to the Mac.

## Outbound (Mac → VPS → internet)

- Change the Mac route `vps-relay` (`x:MtaRoute/set`) from 127.0.0.1:12599 to the tunnel endpoint
  of the VPS submission/relay port, with `authUsername`/`authSecret` of a relay account on the VPS
  (secret in Keychain), or allow the tunnel source as a relay network on the VPS.
- The VPS must permit relaying for learnvibe.ai senders and must not re-sign with its own DKIM for
  learnvibe.ai (the Mac signs). SPF `mx` covers the VPS IP because MX = mail.almaorb.com.
- Then send a test to an external mailbox Marco owns and check SPF/DKIM/DMARC = pass.

## Client access later

Publish HTTPS for JMAP/web admin and IMAPS/submission on mail.almaorb.com via the VPS (certificate
there) or keep them local-only. The Mac's JMAP session already advertises
`https://mail.almaorb.com/jmap/`.
